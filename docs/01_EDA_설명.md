# 1️⃣ EDA & 파생변수 설계 — 쉬운 설명

> 노트북: `notebooks/01_EDA_및_파생변수설계.ipynb`
> 한 줄 요약: **데이터를 통계로 이해하고, 근거 있는 재료(파생변수)를 만들고, 그게 정말 쓸모 있는지 검증한다.**

## 이 단계를 왜 하나요?

모델링을 잘하려면 먼저 데이터를 알아야 합니다. "어떤 알고리즘을 쓸까"보다 "이 데이터가 어떻게 생겼나"가 먼저예요.
좋은 모델은 좋은 알고리즘이 아니라 **좋은 이해**에서 나옵니다.

## 무엇을 했나요? (순서대로)

**① 첫인상 파악**
수치형 변수(수면시간·심박수·BMI 등)의 값 범위가 상식적인지, 범주형 변수에 오타로 생긴 이상한 값은 없는지 확인했습니다.

**② 타깃 분포 확인 — 여기서 중요한 발견**
정답인 `health_condition`이 `at-risk` 86%로 심하게 치우쳐 있었습니다.
→ 그냥 전부 `at-risk`로 찍어도 정확도 86%가 나오므로, **정확도(accuracy)는 이 문제에서 무의미**합니다.
→ 그래서 이 대회의 지표인 **balanced accuracy**(세 클래스 각각의 recall을 평균)를 씁니다.

**③ 결측치가 "정보"인지 검정** ⭐
빈칸(결측)을 무조건 채우기 전에, "값이 없다는 사실 자체가 신호일까?"를 Chi-square 검정으로 확인했습니다.
결측 여부에 따라 타깃 분포가 다르면 → `변수_isna`라는 결측 표시 변수를 만들 근거가 됩니다.

**④ 어떤 변수가 타깃을 잘 가르는지 통계 검정**
- 수치형: **Kruskal-Wallis 검정** (세 클래스 간 값 분포가 다른가?)
- 범주형: **Chi-square + Cramér's V** (범주와 타깃의 관계 세기)
→ p-value만 보지 않고 **효과크기**(eta², Cramér's V)를 함께 봤습니다. 데이터가 크면 p-value는 거의 항상 작게 나오기 때문이에요.

**⑤ 파생변수 설계** ⭐⭐
도메인 지식(건강 상식)을 근거로 새 변수를 만들었습니다. 각 변수에 "왜"가 있습니다.

| 파생변수 | 근거 |
|---|---|
| `*_ord` (서열 인코딩) | 스트레스 low<medium<high 처럼 **순서가 정보**. 트리 모델에 유리 |
| `sleep_debt`, `sleep_ideal` | 권장 수면 7~9시간 기준 부족분/이상범위 |
| `bmi_cat`, `bmi_abnormal` | WHO BMI 구간 (저체중~비만) |
| `lifestyle_risk_score` ⭐ | 위험요인 개수 합산(수면부족·고스트레스·좌식 등). 규칙기반 타깃에 강력 |

**⑥ 파생변수 검증 — "만들었으면 증명하라"**
- **상호정보량(MI)**: 각 변수가 타깃과 얼마나 정보를 공유하는지 측정
- **리프트 테스트**: 원본만 vs 원본+파생을 같은 조건으로 교차검증 → 실제 점수가 오르는지 확인
→ MI 하위 + 점수 상승 없는 파생변수는 **과감히 버립니다**. 변수가 많다고 좋은 게 아니에요(노이즈·과적합).

## 데이터 누수(leakage) 주의 ⚠️

파생변수는 **오직 피처만** 사용해 만들고(타깃 사용 금지), train에서 정한 기준(중앙값·분위수)을 **test에도 똑같이** 적용했습니다. 이걸 어기면 검증 점수는 좋은데 실제 제출 점수는 나쁜 함정에 빠집니다.
