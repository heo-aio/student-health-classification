# 01. EDA & 파생변수 설계

노트북: `notebooks/01_EDA_및_파생변수설계.ipynb`

바로 모델부터 돌리고 싶었지만, 데이터를 먼저 봤다. "어떤 알고리즘 쓸까"는 나중 문제고 "이 데이터가 어떻게 생겼나"가 먼저라고 생각했는데, 실제로 이 단계에서 뒤 작업 방향이 거의 다 정해졌다.

## 1. 데이터 첫인상

수치형(수면시간·심박수·BMI 등) 값 범위가 말이 되는지, 범주형에 오타로 생긴 이상한 카테고리가 없는지부터 확인했다. 크게 튀는 건 없었다.

## 2. 타깃이 심하게 치우쳐 있었다

`health_condition`을 세어보니 `at-risk`가 86%였다. 처음엔 "정확도 잘 나오겠네" 했는데, 생각해보니 전부 at-risk로 찍기만 해도 정확도가 86%다. 그래서 이 문제에서 accuracy는 의미가 없고, 대회 지표인 **balanced accuracy**(세 클래스 recall의 평균)를 봐야 한다는 걸 여기서 확실히 이해했다. 프로젝트 전체 방향을 잡아준 발견이었다.

## 3. 결측치를 무조건 채우지 않았다

개인적으로 제일 인상 깊었던 부분. 원래 결측이면 그냥 중앙값/최빈값으로 채우는 줄 알았는데, "값이 없다는 것 자체가 신호일 수 있다"는 개념을 배웠다. 그래서 결측 여부와 타깃이 관계있는지 Chi-square로 검정하고, 관계가 있으면 `변수_isna` 같은 결측 표시 변수를 만들 근거로 삼았다.

## 4. 어떤 변수가 타깃을 잘 가르는지 통계로 확인

- 수치형: Kruskal-Wallis (세 클래스 간 분포가 다른가)
- 범주형: Chi-square + Cramér's V (관계의 세기)

여기서 배운 건, 데이터가 크면 p-value가 거의 다 유의하게 나온다는 것이다. 그래서 p-value만 믿지 않고 효과크기(eta², Cramér's V)를 같이 봤다.

## 5. 파생변수 만들기 (근거 있게)

"느낌"으로 만들지 않으려고 변수마다 왜 만드는지 이유를 붙였다.

| 파생변수 | 왜 만들었나 |
|---|---|
| `*_ord` (서열 인코딩) | 스트레스 low<medium<high처럼 순서 자체가 정보. 트리 모델에 유리 |
| `sleep_debt`, `sleep_ideal` | 권장 수면 7~9시간 기준 부족분/이상범위 |
| `bmi_cat`, `bmi_abnormal` | WHO BMI 구간(저체중~비만) |
| `lifestyle_risk_score` | 위험요인 개수 합산(수면부족·고스트레스·좌식 등). 타깃이 규칙기반이면 셀 것 같았다 |

제일 기대한 건 `lifestyle_risk_score`였다.

## 6. 만든 변수가 진짜 쓸모 있는지 검증

만들기만 하고 끝내면 안 된다고 해서 두 가지로 확인했다.

- MI(상호정보량): 변수가 타깃과 정보를 얼마나 공유하는지
- 리프트 테스트: 원본만 vs 원본+파생을 같은 조건으로 교차검증해서 점수가 실제로 오르는지

MI 낮고 점수도 안 오르는 변수는 버렸다. 변수가 많다고 좋은 게 아니라는 걸 이때 체감했다.

## 데이터 누수는 계속 조심했다

파생변수는 피처만 써서 만들고 타깃은 안 썼다. train에서 정한 기준(중앙값·분위수)은 test에도 똑같이 적용했다. 이걸 어기면 검증 점수만 좋고 실제 제출은 나빠진다고 해서 계속 신경 썼다.
