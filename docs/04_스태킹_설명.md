# 04. 스태킹 & 최종 스퍼트

노트북: `notebooks/04_스태킹_최종스퍼트.ipynb`

여기가 마지막 단계다. 1등(0.95198)까지 남은 게 0.003 정도인데, 이 구간은 "새 알고리즘 하나"로 메우는 게 아니라 작은 이득을 여러 개 쌓아서 메운다는 걸 배웠다. 그 방법들을 다 넣은 노트북이다.

현재 이 노트북의 스태킹 앙상블로 **0.94904**를 받았다 (제출 파일: `submission_lv5_frac0.3_1seed_5fold.csv`). 단, `frac0.3` = 데이터 30%만 쓴 부분실행이라, 아래 실행 플랜 ③④(full·멀티seed·10-fold·Optuna)까지 돌리면 더 오를 여지가 있다.

## 넣은 방법 (효과 큰 순)

| 방법 | 무엇 | 왜 오르나 |
|---|---|---|
| 원본 데이터 결합 | Playground 데이터는 실제 데이터셋으로 만든 합성 데이터라, 원본을 train에 추가 | 진짜 분포 표본이 늘어남 (상위권이 거의 다 씀) |
| 스태킹 | 4모델 확률을 입력으로 받는 메타모델(로지스틱)을 학습 | "조건부 신뢰 규칙"까지 데이터가 배움 |
| Optuna 튜닝 | 부스팅 하이퍼파라미터를 똑똑하게 탐색(TPE) | 각 모델을 더 짜냄 |
| seed averaging | 같은 모델을 여러 seed로 학습해 평균 | seed 운에 의한 분산 줄임 |
| 클래스별 확률 보정 | 소수 클래스 확률에 배수를 곱해 경계 조정 | balanced accuracy 전용 미세조정 |

## 스태킹이 그냥 앙상블이랑 뭐가 다른가 (내가 정리한 차이)

- 단순/가중 평균: 모델 신뢰도를 사람이(또는 랜덤서치가) 정함
- 스태킹: 4모델의 OOF 확률을 입력 변수로 받는 작은 메타모델을 학습시킴 → "CatBoost가 unhealthy라 하고 LGBM이 애매하면 unhealthy로 본다" 같은 규칙까지 데이터가 알아서 배움

처음엔 둘이 같은 건 줄 알았는데, 스태킹은 "합치는 방법 자체를 학습한다"는 게 다르다는 걸 이해했다.

## 속도 문제를 여기서 해결했다 (OOF 캐싱)

Lv3가 매번 오래 걸리던 게 계속 불편했는데, 한 번 학습한 모델의 OOF/test 확률을 디스크에 저장(`oof_cache/`)해두면 앙상블·스태킹·보정 실험은 재학습 없이 몇 초면 끝난다. 결국 오래 걸리는 건 "학습 한 번"뿐이고, 실험 반복은 빠르다.

## 실행 플랜 (단계적으로)

| 단계 | 설정 | 목적 |
|---|---|---|
| ① | `RUN_FRACTION=0.3` | 파이프라인 검증 (빠름) |
| ② | `RUN_FRACTION=1.0` | 베이스 제출 → 리더보드 확인 |
| ③ | `+ RUN_OPTUNA=True` | 튜닝 반영 |
| ④ | `+ SEEDS=[42,2026,7], N_SPLITS=10` | 최종 풀파워 (GPU, 밤에 걸어두기) |

## 시작 전 꼭 할 일

대회 Data 탭 설명에서 원본 데이터셋 링크를 찾아 `ORIGINAL_SLUG`에 넣기. 제일 싸게 점수 올리는 방법(+0.001~0.005)이라 이건 꼭 해야 한다.

## 스스로 정리한 한마디

0.94904에서 0.95198까지 남은 구간은 어느 정도 운(seed)과 미세조정의 영역이기도 하다. 상위권이라고 마법이 있는 게 아니라 이 방법들을 다 쌓은 것 + 제출을 반복한 것이다. 그리고 public 점수 쫓아서 이것저것 제출하기보다, OOF 기준으로 냉정하게 고르는 게 최종 순위를 지키는 길이라고 배웠다.
