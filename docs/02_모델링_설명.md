# 02. 모델 비교 & 모델 선택

노트북: `notebooks/02_모델비교_및_모델선택.ipynb`

이 단계는 "어떤 모델이 이 데이터에 맞을까"를 감이 아니라 실험으로 답해보는 게 목표였다. 나중에 "왜 이 모델 골랐어요?"라고 물었을 때 "그냥요"가 아니라 "이런 기준으로 골랐습니다"라고 말할 수 있게 하고 싶었다.

## 1. 변수 가지치기

Lv2 검증에서 MI가 0에 가깝던 죽은 변수들(`*_isna`, `n_missing` 등)을 빼고 정예 변수만 남겼다. 안 쓰는 변수를 계속 들고 가면 차원만 늘고 노이즈가 된다.

## 2. 범주형 인코딩 (여기 제일 헷갈렸다)

순서형과 명목형을 다르게 처리해야 한다는 걸 이 프로젝트에서 처음 제대로 이해했다.

| 종류 | 변수 | 인코딩 | 이유 |
|---|---|---|---|
| 순서형 | stress_level, sleep_quality 등 | 서열 숫자 `_ord` | 순서 자체가 정보라 트리가 "stress≥2면 위험" 식으로 바로 나눔 |
| 명목형 | diet_type, gender | OneHot | 순서가 없어서 숫자를 매기면 없는 순서가 생김 |

정리하면 **순서 있으면 서열 숫자, 없으면 OneHot**. 이 한 줄로 외웠다.

## 3. Pipeline으로 묶기

전처리(결측 대치 → 스케일/OneHot)와 모델을 하나의 `Pipeline`으로 묶었다. 이렇게 하면 12개 모델에 똑같은 전처리가 자동으로 붙고, 실수로 test 정보가 새는 것도 막힌다. 처음엔 Pipeline이 왜 필요한지 몰랐는데, 모델마다 전처리를 따로 하다 보면 실수가 나기 쉬워서 필요하다는 걸 알았다.

## 4. 12개 모델 비교 (학습 시간도 같이 측정)

아무거나 12개가 아니라 계열별로 의도를 갖고 골랐다.

- 선형: LogisticRegression, RidgeClassifier, LinearSVC
- 거리/확률: KNN, GaussianNB
- 트리/배깅: DecisionTree, RandomForest, ExtraTrees
- 부스팅: HistGradientBoosting, LightGBM, XGBoost, CatBoost

전체 69만 건으로 12개를 돌리면 너무 느려서 10만 건 층화 샘플로 상대 비교했고, `cross_validate`로 balanced accuracy와 `fit_time`을 같이 쟀다.

## 5. 시간 vs 성능 산점도

"왼쪽 위 = 빠르면서 정확"으로 보는 그래프. 후보를 좁히는 데 썼다.

## 6. 왜 이 모델을 골랐는지 기준을 먼저 정했다

숫자 나오고 나서 고르는 게 아니라, 고르는 기준을 미리 정했다: ① balanced accuracy(주지표) → ② 안정성(fold별 편차) → ③ 효율(학습 시간) → ④ 과적합 여지.

## 7. 튜닝 → 전체 학습 → 제출

RandomizedSearchCV로 가볍게 튜닝하고, hold-out으로 정직하게 성능(혼동행렬)을 확인한 뒤 전체 데이터로 다시 학습해 `submission.csv`를 만들었다.

## 이 단계에서 크게 깨달은 것

12개 모델 비교는 사실 **공부/발표용**이지 점수용이 아니었다. 실제 점수에 기여하는 건 부스팅 4종뿐이고, KNN·NB·선형·단일 트리는 애초에 우승 후보가 아니다. 그래서 이 노트북이 오래 걸린 건 "이길 수 없는 모델까지 다 돌려서"다. **학습이 오래 걸린다고 좋은 모델이 나오는 게 아니라는 것** — 이게 이 단계에서 제일 크게 배운 점이다. 실제 점수는 뒤 Lv4·Lv5의 부스팅 앙상블에서 나왔다.
