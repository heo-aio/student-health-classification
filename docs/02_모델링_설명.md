# 2️⃣ 모델 비교 & 모델 선택 — 쉬운 설명

> 노트북: `notebooks/02_모델비교_및_모델선택.ipynb`
> 한 줄 요약: **12개 모델을 같은 조건에서 공정하게 비교하고, 근거를 가지고 최종 모델을 고른다.**

## 이 단계를 왜 하나요?

"어떤 모델이 이 데이터에 맞을까?"를 감이 아니라 **실험으로** 답하는 단계입니다.
또 발표/포트폴리오에서 "아무거나 골랐다"가 아니라 "**기준을 세우고 골랐다**"고 말할 수 있게 합니다.

## 무엇을 했나요?

**① 변수 가지치기 (Lv2 검증 결과 반영)**
Lv2에서 MI가 0에 가까웠던 죽은 변수들(`*_isna`, `n_missing` 등)을 제거하고 **정예 변수 세트**만 남겼습니다.

**② 범주형 인코딩 전략** (자주 헷갈리는 부분)

| 종류 | 변수 | 인코딩 | 이유 |
|---|---|---|---|
| 순서형 | stress_level, sleep_quality 등 | 서열 숫자 `_ord` | 순서 자체가 정보 → 트리가 "stress≥2면 위험" 분기 |
| 명목형 | diet_type, gender | OneHot | 순서가 없음 → 숫자 매기면 가짜 순서 생김 |

> 핵심: **순서 있으면 서열(숫자), 없으면 OneHot.**

**③ Pipeline 아키텍처 구성** ⭐
전처리(결측 대치 → 스케일/OneHot)와 모델을 **하나의 `Pipeline`**으로 묶었습니다.
→ 이렇게 하면 12개 모델에 동일한 전처리가 자동 적용되고, 데이터 누수도 막힙니다.

**④ 12개 모델 비교 (학습 시간 측정 포함)**
계열별로 의도를 갖고 배치했습니다:
- 선형: LogisticRegression, RidgeClassifier, LinearSVC
- 거리: KNN / 확률: GaussianNB
- 트리/배깅: DecisionTree, RandomForest, ExtraTrees
- 부스팅: HistGradientBoosting, **LightGBM, XGBoost, CatBoost**

→ 전체 69만 건은 너무 느려서 **10만 건 층화 샘플**로 상대 비교하고, `cross_validate`로 balanced accuracy와 `fit_time`을 함께 측정했습니다.

**⑤ 시간 vs 성능 산점도**
"왼쪽 위 = 빠르면서 정확(가성비 최고)"를 한눈에 보는 그래프. 후보를 압축하는 데 씁니다.

**⑥ "왜 이 모델을 선택했는가" 의사결정 기록** ⭐
선택 기준을 우선순위로 정했습니다: ① balanced accuracy(주지표) → ② 안정성(fold 편차) → ③ 효율(학습 시간) → ④ 과적합 여지.

**⑦ 선택 모델 튜닝 → 전체 학습 → 제출**
RandomizedSearchCV로 가볍게 튜닝하고, hold-out으로 정직한 성능(혼동행렬)을 확인한 뒤, 전체 데이터로 재학습해 `submission.csv`를 만들었습니다.

## ⚠️ 이 단계에 대한 솔직한 메모

12개 모델 비교는 **학습/발표용**이지 점수용이 아닙니다.
실제 점수에 기여하는 건 **부스팅 4종뿐**이고, 나머지(KNN·NB·선형·단일 트리)는 우승 후보가 아니에요.
그래서 이 노트북이 오래 걸리는 건 "이길 수 없는 모델까지 다 돌리기 때문"입니다.
**학습 시간이 길다고 좋은 모델이 나오는 게 아니다** — 이게 이 단계의 가장 큰 교훈이었습니다.
(점수 생산은 Lv4·Lv5의 부스팅 앙상블에서 합니다.)
